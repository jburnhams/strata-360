# Repository Guidelines

- Python application code lives in `src/strata360/`; the React web app lives in `web/src/` and builds into `src/strata360/server/static/`.
- Python tests live under `tests/`, grouped by type:
  - `tests/unit/`: fast, isolated tests of pure logic (synthetic data, fakes). No ffmpeg, models or real footage.
  - `tests/integration/`: slower tests that run ffmpeg/ffprobe, the CLI, the server, or the full optimiser. They build a tiny synthetic OSV with `tests/utils/synthetic_osv.py` (the `synthetic_osv` fixture); real footage (`videos/`) is gitignored and never required.
  - `tests/utils/`: shared helpers (fakes for HTTP/subprocess, project builders). `tests/conftest.py` holds shared fixtures and restores patched globals after each test; `tests/unit/conftest.py` makes the unit suite hermetic (isolated home, no network).
  - Read `tests/README.md` before writing any Python test: fixtures, conventions and a per-module coverage ledger.
- Web tests live in `web/tests/{unit,integration,utils}` (vitest; unit runs in node, integration in jsdom). Backend calls are mocked with msw; read `web/tests/README.md` before writing any.
- Python tooling is **uv**: `uv sync` builds `.venv` from the committed `uv.lock` (the light dependencies and the dev group: pytest tooling, ruff, pyright, ty, mcp, numba). The heavy model stack (torch, the vision and CV models) is deliberately **not** locked, because the right build depends on the card: it stays in `requirements.txt`, `requirements-vision.txt` and `requirements-cv.txt`, installed into the machine's environment on top (`uv sync --locked --no-dev --inexact`, then `uv pip install -r requirements.txt`; an exact sync would remove torch). CI installs the CPU torch with `.github/actions/torch-cpu`. `strata-python` and `strata-models-client` are git dependencies (`uv.lock` pins the commit; `.github/workflows/upgrade-strata-python.yml` moves it weekly through a PR that has passed the gate). Commit `pyproject.toml` and `uv.lock` together.
- Commands (Python, from the repo root, via `uv run ...`):
  - `scripts/check` is `uv run --locked strata-check`: `uv lock --check`, `ruff check`, `ruff format --check`, `pyright` and `ty`, then the unit tests with coverage. Run it before every commit (`--fast` skips the tests, `--fix` applies safe ruff fixes). Style is `ruff format` at line length 120; pyright is strict for the files under `strict` in `pyproject.toml` (a ratchet: type a file fully, then add it; never remove one) and warns elsewhere. Never skip a test or a check to get green; many existing-code ruff rules are ignored in `pyproject.toml`, each with its reason, and are to be cleaned up.
  - `uv run pytest tests/unit --cov` runs the unit suite with coverage (random order via pytest-randomly; `-n auto` runs in parallel; `diff-cover` checks the lines a change touches).
  - `uv run pytest tests/integration -n auto` runs the integration suite (needs ffmpeg with libx265).
- Commands (web, from `web/`): `npm run test:unit`, `npm run test:integration`, `npm run test:coverage:gate` (unit + integration together, what CI gates on: floors in `web/coverage-floor.json`), `npm run test:coverage` (unit only, informational), `npm run test:coverage:all` (unit + integration, no gate), `npm run typecheck`, `npm run build`.
- Python coverage is calculated from the unit suite only (`fail_under` in `pyproject.toml`). Web coverage is gated on unit + integration together (`web/coverage-floor.json`, read by `web/vitest.gate.config.ts`; most web tests are jsdom integration tests). Both floors only ratchet up.
- New tests use pytest style (`def test_...` with `assert`; use the `monkeypatch`/`tmp_path` fixtures instead of patching globals by hand).
- Cross-platform: ffmpeg hardware options (decode acceleration, encoders, GPU) come from `src/strata360/hw.py`, which picks VideoToolbox on macOS, NVENC on Windows when present, and software otherwise; never hard-code `videotoolbox` elsewhere. `STRATA_HWACCEL` and `STRATA_ENCODER=software` override it. AMD GPU on Linux (Radeon 780M, 2026-10-26): `scripts/setup_env.sh` swaps PyPI's CUDA torch, torchaudio and torchvision for the ROCm 6.4 builds (torchvision must match, or `torchvision::nms` does not exist); `strata360/__init__.py` sets HSA_OVERRIDE_GFX_VERSION=11.0.0 for gfx1101-1103 before torch loads; `hw.gpu_is_amd()` makes the GPU duty polite (0.6) because that GPU draws the screen. Whisper stays on the CPU (ctranslate2 has no ROCm build).
- OS differences other than video hardware (file locks, process liveness and termination, priority, free memory, how to start the CLI) live in `src/strata360/oslib.py`; do not import `fcntl` or call `os.kill(pid, 0)` elsewhere (on Windows that kills the process).
- GitHub Actions: `unit.yml` (Python 3.11 to 3.13 on Linux, plus macOS, plus Windows, unit tests with coverage, lint, web typecheck, unit tests and build) and `integration.yml` (synthetic-clip integration tests on Linux, macOS and Windows, plus web integration tests; also weekly). Model-dependent checks (transcription, alignment, exposure on real footage) are run by hand: see `docs/overview.md` section 0.
- Docs live in `docs/`: `overview.md` (index of the design brief, one file per section in `docs/overview/`; code comments cite its sections as "README N"), `progress.md` (index of the log of findings in `docs/progress/`), `implementation-plan.md` (what to build next: front page, one file per milestone in `docs/plan/`), `prompts/` (test-writing prompts).
