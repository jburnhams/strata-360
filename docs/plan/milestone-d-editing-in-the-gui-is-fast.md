## Milestone D: editing in the GUI is fast

### D1. Timeline editing (M)
- Drag a window's edges; they snap to beats and to safe cut points with the V5 rules (never into dialogue).
- "Suggest again" for one window or a selected range (re-plan only the unlocked part with a new seed); keep the last three versions to step back.
- A map strip under the timeline (positions from `gps/context.py`).
- **Done when:** web integration tests (msw) for drag-snap and suggest-again; Python unit tests for the partial re-plan leaving locked windows identical (P5-30).
- **Status (19 Oct 2026): built for the beat planner's film.** `chrono.replan` plans a run of windows again inside the footage between its neighbours, in the same beats, with a shaken choice of moments; every other window (and every locked one) keeps its footage, length, technique and variant seed, so its segment is identical (P5-30, `test_suggest_again_replans_the_unlocked_part_and_leaves_locked_windows_identical`). Dragging the cut between two windows (`project.move_edge`, a roll edit: one window gets longer, the next starts later in its clip) snaps to whole beats inside the room the server gives (`edge_room`: the shortest window, the longest technique, the stretches and the clips' other windows) and to the nearest beat that does not land inside the wearer's words (`blocks.speech_spans`), then locks both windows. "Suggest again" works on one window or a shift-clicked run; the last three versions (plan and changes) are kept in `plan_history.json` for "Step back". A lock, a technique or a transition no longer plans new windows when nothing that shapes them changed (`plan.inputs`), so a drag or a suggestion survives them; a new length, tempo, seed, ban or clip weight plans the whole film again (locks kept). The map strip under the timeline shows where each window was filmed (`gps/context.py`). Not done: a film planned from the script is not editable this way yet (its windows come from the script's items; change it in the Film script panel).
